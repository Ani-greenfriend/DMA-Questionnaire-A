## Section 1 — Tool Summary

**Tool name:** Apus DMA — Expert Survey

**What it does:** A web page opened through one survey link and the survey password (the same for everyone invited to that survey), where one expert rates the ESRS double-materiality topics (Impacts, Risks, Opportunities — "IROs") of one assessment. It asks the expert's name and email, shows one topic per page with every applicable criterion, collects a justification for each rating, saves progress so the expert can leave and resume (same browser automatically, any device through a personal resume link), and submits the complete response as one record.

**Who uses it:** Invited experts and stakeholder representatives of a client company — for example employees, suppliers, customers, investors, lenders, NGOs, subject-matter experts — and representatives of **silent stakeholders** (parties that cannot speak for themselves, such as nature, represented by a proxy such as an ecologist or nature NGO). No account is needed; the survey link and password open the survey, and a personal resume link brings each expert back to their own draft.

**Why it exists:** Lets a sustainability consultant collect individually rated, justified expert input for an ESRS double materiality assessment at the granularity (Scale / Scope / Irremediability / Likelihood, or Magnitude / Likelihood) that makes the result audit-defensible, while recording who responded (name and email as given by the expert, matched by the consultant against the expected participants in Tool B), without any expert creating an account.

**Build status:** Iteration — v2.0 (built in session 5, personal invitation link per expert, six link-code functions) is changed to v2.1: one survey link plus one automatically generated password per survey, name and email on About you, a personal resume link per response, and resume-code functions replacing the link-code functions. Everything else in v2.0 stays. The v2.0 build status, for history: the previous version (v1.1, "Participant Questionnaire") was an anonymous questionnaire opened through one shared link per assessment, with per-criterion ratings, an optional overall comment, no justification, no stakeholder-expertise capture and no save-and-resume. This build renames the tool, replaces the shared link with personal invitation links, adds the About you screen, per-rating justifications, save and resume, and the submission record, and changes the GDPR outcome from "not applicable" to "applies". Only the demo assessment (`acme-2026`) exists; there is no real response data to migrate.

## Section 5 — Data Architecture

### Terminology (applies to both specs)

- **Expert survey** — an assessment type where invited experts answer through Tool A. Database value: `expert_survey`.
- **Expert live session** — an assessment type run by the consultant in Tool B with a group. Database value: `expert_live_session`.
- **Cycle** — one DMA round for one client (for example a financial year). It groups the expert survey and the expert live session that are combined into one result.
- **Assessment** — one expert survey or one expert live session inside a cycle.
- **Expected participant** — one person the consultant expects to answer an expert survey (name, email, group). Stored in the table `invitations`, which keeps its name. From v2.1 it no longer hands out a link; responses are matched to it by email in Tool B.
- **Survey link** — `[Tool A site address]/survey/[assessment slug]`, the same for everyone in one expert survey.
- **Survey password** — one per expert survey, generated automatically by Tool B when the survey is created, in readable-word format (for example `river-maple-42`). Stored in `survey_access`.
- **Resume code / resume link** — a random code (at least 24 characters) created with each draft; the resume link is `[Tool A site address]/survey/[assessment slug]/[resume code]`.
- **Submission** — one expert's whole response (survey) or one live session's whole result.

## Section 6 — Access and Permissions

Not applicable as a login — no authentication on this tool (A1). Experts never become Supabase Auth users and the survey never signs anyone in; "Request my link"-style or magic-link logins are out of scope (Section 12).

**Access from v2.1:**
- **Survey link** `/survey/[assessment slug]` — shared by everyone in one expert survey. It shows the password screen with the client logo and survey title (display content the public side may read, as in v2.0).
- **Survey password** — generated by Tool B, stored in `survey_access`, which the public side can never read. It is checked only inside the database by `check_survey_password` and again by `start_response`. It is never returned, logged in the browser or stored in the browser.
- **Starting a response** — a correct password plus consent, name, email and About you creates the draft and returns its **resume code**. From then on every read and write of that draft goes through functions keyed by the resume code (get draft, save progress, submit). The code is the only key to the draft: resuming by name or email is never possible.
- **No direct table access** for the public side on `survey_access`, `invitations`, `submissions`, `ratings` or `topic_justifications`: no policy and no grant of any kind. Display tables (assessments, iros, clients, stakeholder_groups, and cycles by column grant) stay readable exactly as in v2.0.
- Nothing is ever deleted from the public side. A submitted response cannot be changed.
- **Abuse control:** the password is the abuse control for starting a response. The builder decided against a CAPTCHA to keep the start step light and to avoid a server function. There is no rate limit; automated password guessing is therefore not blocked (accepted risk, Section 15).

The row-level access rules live in access-matrix.md, produced by the Access Architect; Claude Code builds the functions and policies from that file. This section does not duplicate the grid.

## Section 7 — GDPR

**GDPR outcome:** Applies — personal data is collected through the tool's forms. The survey is no longer anonymous.

**Personal data collected:**
- **Name and email**, typed by the expert on About you (required; self-declared, not verified)
- Fields of expertise and the written expertise explanation (which may identify a person in a small group)
- Optional job title or role
- Optional basis for representation (may name a person or organisation)
- Overall comment and justifications (free text — may contain names or other personal information)
- From v2.1 the response itself carries the name and email the expert typed. The consultant matches it by email against the expected participants list in Tool B. Names are not shown in results unless the consultant reveals them (Tool B).

**Business reason for holding name and email (for the legal check):** audit traceability — being able to show who responded and that responses come from the people the consultant asked, matched against the expected participants list, rather than fabricated input. Identity is self-declared, and the methodology says so (Tool B report).

**Consent checkpoint on the form:** Yes — a checkbox and data statement must appear on the Welcome screen, before the expert starts. The checkbox must be ticked to continue. `consent_given_at` is recorded on the submission.

**Data statement text shown to users at the point of collection:**
> Your name, your email, your expertise details, your answers and, if you choose to give it, your job title are stored securely and used only to run and document this materiality assessment. Your name and email are not shown in the results. Your answers may be shared with the client company and its auditor. You can request deletion or anonymisation at any time by contacting: **anikalerch@greenfriend.org**.

**Deletion mechanism:** On request, the consultant (in Tool B) clears the name, email and optional title on the expert's submission, and the name and email on the matching expected participant (shown as "Anonymised"). Ratings, justifications, stakeholder group and expertise remain, so the assessment stays intact and traceable, but the response can no longer be connected to a person. Requests go to **anikalerch@greenfriend.org**, and the consultant (greenfriend) processes them.

> This is a legal requirement in the EU. The deletion contact (anikalerch@greenfriend.org) is confirmed. Whether the anonymisation approach and the legal basis for holding invitation details are acceptable must still be confirmed with legal advice **before real experts are invited** (it does not block the build). This spec is not legal advice.

## Section 8 — Screen and UI Structure

Every screen shows the **client company's logo prominently at the top** (or a dashed-border placeholder if none is uploaded) and a small, muted "Hosted on ✈ apus" credit at the very bottom. The Apus mark is never the prominent header.

### Password (the survey link's entry screen) — new in v2.1

- **Purpose:** Let only people who received the survey link and password start a response.
- **What is visible:** Client logo; the title ("[Company name] sustainability survey"); a **Survey password** field with the hint "You'll find the password in the email with your survey link"; a "Continue →" button.
- **User actions:** Type the password; continue.
- **What happens next:** Correct → Welcome. Wrong → "That password doesn't match. Check the email with your survey link." If the survey is Closed or Completed, or its end date has passed → the form is replaced by "This survey is closed". If the survey is Draft or Scheduled, or before its start date → "This survey isn't open yet". The typed password is kept only in the page's memory until the draft is created; it is never stored in the browser.
- **Same browser:** if the browser remembers a draft for this survey (its resume code), the password screen is skipped and Welcome opens with "Continue where you left off →" and a small "Start a new response instead" link (which forgets the remembered code and shows the password screen).

### Welcome (with consent)

- **Purpose:** Introduce the survey, set expectations and obtain consent before any question is asked.
- **What is visible:** Client logo; title ("[Company name] sustainability survey", or "Sustainability survey" if no company name); the consultant-edited welcome text; three fixed bullets — "Your answers are linked to the name and email you give", "Time needed depends on the number of topics — you can save and continue later at any time", "Not sure about something? You can skip any criterion"; the **data statement** from Section 7; a **consent checkbox**; the note "Once you start, you'll get a personal resume link to continue on another device"; a "Get started →" button.
- **User actions:** Tick the consent checkbox; click "Get started →" (disabled until ticked). If the visitor arrives with a draft (remembered by this browser, or through a resume link), the button reads "Continue where you left off →".
- **What happens next:** New visitor → About you. Returning visitor with a draft → the first unfinished topic, with earlier answers and justifications restored.

### About you

- **Purpose:** Capture the expert's expertise and the perspective they answer from. The expert fills in everything themselves — nothing is pre-filled from the invitation.
- **What is visible:** "← Back"; "About you"; **Your name** (required) and **Your email** (required, format-checked), with the note "Your name and email tell the assessment owner who answered. They are not shown in the results."; **Field(s) of expertise** — multi-select of E1 Climate change, E2 Pollution, E3 Water and marine resources, E4 Biodiversity and ecosystems, E5 Resource use and circular economy, S1 Own workforce, S2 Workers in the value chain, S3 Affected communities, S4 Consumers and end-users, G1 Business conduct, and Other / cross-cutting; **Explain your expertise** (short text, required); **Job title or role** (optional, with the hint "keep it general, for example 'Head of HR'"); **Which group best describes you?** — two labelled option grids, "Impact perspective" (default options: Employees, Suppliers, Local community, Customers, Workers in the value chain, NGOs / civil society, plus any **silent stakeholder** groups the consultant enabled, for example Nature and ecosystems, Species and biodiversity, Future generations) and "Financial perspective" (default options: Investors / shareholders, Lenders / creditors, Executive management, Supervisory board, Analysts / rating agencies). Options come from the assessment's stakeholder groups in Tool B. When a silent stakeholder group is chosen, an optional field appears: "On what basis do you represent it? (for example a study, method or mandate)".
- **User actions:** Enter name and email; choose at least one expertise; write the explanation; optionally add a title; select exactly one group; click "Continue →" (disabled until name, a valid email, expertise, explanation and one group are set).
- **What happens next:** For a new response, `start_response` creates the draft (checking the password again) and returns the resume code; the browser remembers the code for this survey; the page moves to **Your resume link**. For an existing draft, the changes are saved and the page moves to Rating Criteria.

### Your resume link — new in v2.1

- **Purpose:** Hand the expert their way back before they start rating.
- **What is visible:** "You're all set"; the **resume link** with a "Copy link" button; "Keep this link to continue on another device. On this browser, the survey remembers your progress automatically."; "Continue →".
- **User actions:** Copy the link; continue.
- **What happens next:** Rating Criteria. Shown once per new response.

### Rating Criteria

- **Purpose:** Explain what each criterion means before the expert uses it.
- **What is visible:** "← Back"; "How to rate each topic"; one or both blocks depending on the assessment's scope — "Impacts on the environment or society (positive or negative)" (Scale, Scope, Irremediability, Likelihood, each with a plain-language description) and/or "Financial risks and opportunities" (Magnitude, Likelihood); a short note that every rating needs a short justification and that any criterion can be skipped.
- **User actions:** Click "← Back" or "Continue →".
- **What happens next:** Moves to the first Topic rating page.

### Topic rating (repeats once per IRO in the assessment's scope)

- **Purpose:** Collect every applicable criterion and its justification for one IRO.
- **What is visible:** "← Previous topic" (hidden on the first topic); "Topic X of Y"; a progress bar; an IRO-type badge (Negative impact, Positive impact, Risk, Opportunity) and an Actual / Potential badge; the topic name and description; then every applicable criterion stacked vertically (see Section 9 for which criteria appear) — each with its large label, plain-language description, a row of six buttons (0–5), a live label showing what the hovered or selected value means, its own **Skip** control (with the tooltip "For anyone unsure or without direct expertise on this specific topic — it's fine to skip rather than guess") and, **when the assessment's justification mode is per criterion**, a **justification box** below the rating (compact, grows as the expert types; required once a value is chosen; hidden while skipped). When the mode is **per topic**, one justification box sits at the bottom of the topic instead. A skipped criterion shows "Skipped — that's okay, not everyone has a view on every topic" with an "Answer instead" link. A prominent **"Save and continue later"** button is visible on every topic page.
- **User actions:** Answer or skip each criterion; write the justification; go back; advance; save and continue later.
- **What happens next:** "Next topic →" (or "Continue →" on the last topic) saves the draft and is disabled while `assessments.mandatory = true` and any criterion on the page is neither answered nor skipped, or while a required justification is empty. Advancing past the last topic moves to Submit.

### Save and continue later (confirmation)

- **Purpose:** Let the expert leave on purpose and make sure they know how to come back.
- **What is visible:** "Your progress is saved."; the **resume link** with a "Copy link" button; the message "This link brings you back to your answers on any device — keep it. Anyone with this link can open your draft. Lost it? Contact the person who invited you."; a note that unfinished answers are **not counted** in the results until the survey is submitted.
- **User actions:** Copy the link; close the page; or click "Back to the survey".
- **What happens next:** Opening the resume link later, on any device, resumes at the first unfinished topic. On the same browser, reopening the survey link also resumes.

### Submit

- **Purpose:** A final confirmation step before the response is sent, plus a chance to add anything not covered by the structured questions.
- **What is visible:** "That's everything"; a note that "Previous" can still be used to review answers and that submitting is final; the optional **"Any other comments?"** textarea (labelled "anything you didn't get to say above, or context you think matters") directly above the Submit button; any missing required justification or unanswered criterion is listed if the assessment is mandatory.
- **User actions:** Type an optional comment; click "Submit survey →".
- **What happens next:** The response is written as one complete, all-or-nothing submission — every rating row and justification with the status set to submitted, or nothing at all — then moves to Thank you, and the browser forgets the remembered resume code for this survey (the survey link starts fresh on this browser). If saving fails, the expert stays on this screen with their answers intact and can retry.

### Thank you

- **Purpose:** Close the loop for the expert.
- **What is visible:** "Thank you for your participation" and a short note that the answers will feed into the company's materiality assessment alongside everyone else's.
- **User actions:** None — end of flow.

### Already submitted / link not valid / survey closed or not open

- **Purpose:** Handle links that cannot be used.
- **What is visible:** Already submitted — opening a resume link whose response is submitted shows "You've already submitted this survey. Thank you." (read-only, no answers shown). Link not valid — an unknown resume code or survey name shows "This link isn't valid. Please contact the person who invited you." Survey closed — "This survey is closed" when the assessment is Closed or Completed or its end date has passed; this also applies to resume links (a draft cannot be continued or submitted). Not open — "This survey isn't open yet" when the assessment is Draft or Scheduled or before its start date.
- **User actions:** None.
- **What happens next:** End of flow.

## Section 9 — Logic and Calculations

**No calculation.** This tool captures a `value` (0–5) or empty (skipped) plus a justification per criterion and hands it to the database exactly as entered. All formulas — severity, override, impact and financial scores, materiality, discrepancy — live in Tool B (Section 9 of its spec).

**Display rules — which criteria a topic page shows** (this is which questions to ask, not a calculation):

| IRO | Criteria shown |
|-----|----------------|
| Negative impact, potential | Scale, Scope, Irremediability, Likelihood |
| Negative impact, actual | Scale, Scope, Irremediability (likelihood is not asked — an actual impact is already occurring) |
| Negative impact flagged **potential human rights impact** (owner-set flag on the IRO in Tool B) | Scale, Scope, Irremediability (likelihood is not asked — severity takes precedence) |
| Positive impact, potential | Scale, Scope, Likelihood |
| Positive impact, actual | Scale, Scope |
| Risk or opportunity | Magnitude, Likelihood |

**Gating rules:**
- The survey password must be correct before a response can be started (checked in the database only).
- Name, a valid email, stakeholder group, at least one expertise and the expertise explanation are required before the draft is created.
- A justification is required whenever a criterion has a value (per criterion mode), or once per topic when any criterion on it has a value (per topic mode). Skipped criteria need no justification.
- "Next topic" stays disabled while `assessments.mandatory = true` and any criterion on the page is neither answered nor skipped.
- Progress is saved on every "Next topic", every "Previous topic", and on "Save and continue later".
- One submission exists per resume code. After submission, no further changes are possible from the public side.
- A draft is reopened only by its resume code (remembered by the same browser, the resume link, or a link re-sent by the consultant); never by name, email or password.
- New responses, saves and submits are accepted only while the assessment is Active and inside its start and end dates.
- Draft responses are never counted in any result.

**Edge cases:** If the same resume link is open in two tabs, the most recently saved answers win (last write wins). If the assessment is closed while a draft is open, the expert sees the "survey closed" message on their next save and cannot submit. If an expert starts twice (for example on two devices without using their resume link), two responses exist; the builder accepted this — there is no duplicate detection.
